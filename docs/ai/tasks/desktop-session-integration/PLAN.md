# 구현 계획: Desktop 세션 통합 관리자

## 승인 범위와 위험

사용자가 승인한 구현 방향을 기록한다. 위험도 High: 기존 터미널 중심의 목록/상태/실행 수명주기를 Desktop 연동으로 바꾸는 다중 계층 변경이다. 원본 데이터 형식과 설치된 Desktop 앱은 수정하지 않는다.

## 확인한 사실

- 원본은 Wails/Go, Svelte, xterm.js를 사용한다.
- App.startup과 세션/상태/종료 로직에 터미널 부수 효과가 있어 실행 버튼만 교체할 수 없다.
- 기존 Python 프로젝트 D:/repos/intellian/Session_Manager에 Claude 조회, 로컬/SSH 상태, 기존 세션 독립 창 브리지가 있다.
- Claude 새 작성 화면 링크는 일반 Desktop 창을 여는 경로이며, 새 대화를 독립 창으로 여는 것과 다르다.
- Codex 공식 링크는 대화 열기를 지원한다. 설치본에 내부 open-in-new-window 명령이 있지만 외부 링크 처리와 분리되어 있다.
- 현재 원본 프런트엔드 빌드와 타입 검사는 통과한다. 전체 Go 검증은 원본 PortAudio의 pkg-config 의존성 누락으로 실패한다.

## 가정과 미결 사항

- 초기 대상 OS는 현재 사용 중인 Windows다.
- UI의 사이드바/테마/프로젝트 구성을 활용하고 중앙 터미널은 세션 상세와 열기 액션으로 바꾸는 방향을 승인받았다. 세부 화면 배치는 최소 구현 시 확인한다.
- Codex는 네이티브 Windows UI Automation 메뉴의 새 창 명령 후 공식 URI를 여는 경로로 로컬 기존 세션을 검증했다. 재사용 가능한 호출 및 결과 확인을 구현한다. 기존 창 이동만으로 성공 처리하지 않는다.
- Desktop 목록/현재 실행 상태는 각각 실제 데이터와 근거가 필요하다. 원본 터미널 상태를 재사용하지 않는다.

## Step 1 — Clone, 기준 검증, 독립 창 연동 확인

- 대상: 저장소 초기 설정, docs/ai/tasks/desktop-session-integration, verification/desktop-window-contract.json.
- 기존 Python 기능과 Codex 공식 문서/설치본의 창 열기 계약을 조사한다.
- 가능하면 임시 세션으로 실제 창과 세션 ID를 대조한다. 실제 검증이 없으면 통과로 기록하지 않는다.
- 완료 기준: Claude/Codex의 선택한 기존 세션을 외부 프로그램에서 독립 창에 여는 경로와 실제 결과를 모두 확보한다.
- 중단 조건: 외부 호출 경로 미확보, 앱 설치 파일 변조 필요, 세션 복제/메시지 전송이 필요하거나 사용자 요구와 다른 동작만 가능한 경우. 이 상태에서는 Step 2로 넘어가지 않는다.
- 체크포인트: bootstrap 문서/근거만 독립 커밋 가능. 연동 완료 커밋은 실제 검증 후 생성한다.

## Step 2 — 원본 UI에서 세션 하나의 창 열기

- 확정 대상: desktop의 별도 Wails 진입점/네이티브 Codex helper/Python bridge, frontend의 Desktop 전용 진입점/화면, Desktop 빌드 스크립트. 원본 CSS 토큰과 AgentIcon을 재사용한다.
- 원본 앱의 startup은 터미널 부수 효과를 갖고 음성 의존성도 연결하므로 Desktop 전용 Wails 진입점을 분리한다. Wails와 Svelte, Python 표준 라이브러리만 사용하며 새로운 UI 프레임워크를 도입하지 않는다.
- 기존 Claude 모듈을 먼저 재사용하며 불필요한 Go 재작성을 피한다.
- 터미널 생성/설치/전송/종료 부수 효과 없이 선택한 Desktop 대화를 연다.
- 검증: 잘못된 ID, 앱 미설치/연동 거절, 중복 클릭, 실제 대상 창/대화 일치, 프런트엔드 빌드/타입 검사.
- 완료 기준 및 체크포인트: 두 Desktop의 실제 단일 세션 연결과 검증을 마친 후 scoped commit.

## Step 3 — 목록, 그룹, 상태 연결

- Desktop 데이터 조회, 식별자 구분, 검색/그룹, 상태 근거를 연결한다.
- Desktop 세션 ID와 원본 터미널 세션 ID를 혼동하지 않는다.
- 그룹은 관리자 전용 저장소에 보관한다. 대화 원본을 삭제하거나 변경하지 않는다.
- 검증: 두 앱의 목록, 동명 세션/계정 구분, 갱신 실패와 오래된 상태, 그룹 저장/재시작, 실제 창 열기 회귀, UI 화면 확인.
- 완료 기준 및 체크포인트: 요구한 디자인과 동작을 실제 앱에서 확인한 후 scoped commit 및 HANDOFF 갱신.

## 범위 제한

인증/권한 우회, Desktop 설치 파일 수정, 새로운 프롬프트 전송, Codex 독립 창 요구 완화, unrelated upstream 경고/의존성 갱신은 포함하지 않는다.
