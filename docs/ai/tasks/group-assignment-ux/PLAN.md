# Groups 통합 목록과 영구 그룹 연결

- 날짜: 2026-11-02 (Asia/Seoul)
- 스킬: software-change-workflow
- 상태: 2026-11-02 사용자가 전체 계획의 구현·검증을 승인했다. Step 1 완료, Step 2 진행.
- 위험: High. Desktop 전용 저장 형식과 bridge 응답, 분류 및 UI를 함께 확장한다.
- 체크포인트: 각 Step 검증 후 그 Step 파일만 커밋한다. 기존 미추적 backup은 제외한다.

## 확인된 사실

- Desktop 화면은 frontend/src/DesktopApp.svelte다. 현재 GROUPS, AUTO PROJECTS, CLAUDE GROUPS, CODEX PROJECTS, PROJECT FOLDERS로 나뉜다.
- desktopProjects.ts의 classifyProjects가 수동 소속을 먼저 제외한 뒤 자동 분류한다. 같은 루트·이름의 제공자 간 항목만 제한적으로 합치며 경로·계정 경계를 보존한다.
- 그룹은 desktop/bridge.py가 공용 Python GroupStore로 %APPDATA%/DesktopSessionManager/groups.json에 저장한다. 현재 version 1에는 id/name/members만 있으며 그룹 연결은 없다.
- 그룹 원본은 Claude/Codex 메타데이터에서 읽는다. 원본 데이터는 수정하지 않는다.
- 세션 행의 우클릭 메뉴는 이미 있으며 현재 “세션 상세”만 제공한다. 키보드 진입, 화면 경계 보정, 바깥 클릭·Escape 해제 처리가 있다.
- 기존 사용자 그룹에는 여러 소속이 허용된다. 마지막 소속 해제 후 자동 분류로 돌아간다.
- desktop/main.go는 모든 그룹 변경 요청을 mutex로 직렬화한다. 새 그룹 변경 action에도 기존 잠금을 적용할 수 있다.
- 기준 테스트: Node 분류/트리 19개와 Desktop Python 48개 통과(2026-11-02).
- 관련 기존 규칙: docs/ai/tasks/unified-project-view/SPEC.md. 이번 요청은 영역 분리 보존과 영구 연결 제외 조항을 대체한다. 나머지 자동 동일성·원본 보존 규칙은 유지한다.

## 확정 요구와 제안하는 적용 기준

### 목록과 아이콘

- Groups 한 영역에 사용자 그룹과 자동 그룹을 이름순으로 연속 표시한다. 제공자별 소제목과 자동/수동 별도 영역은 없앤다.
- 같은 표시 이름이라는 이유만으로 별개 항목을 합치지 않는다. 동명 항목은 경로/출처 보조 문구로 구별한다.
- 실제 소속 세션이 Claude뿐이면 Claude, Codex뿐이면 Codex 아이콘을 표시한다. 양쪽 모두 있으면 한 아이콘 영역의 왼쪽 Claude/오른쪽 Codex를 각각 50% 잘라 합친다. 보조 설명은 “Claude · Codex”로 제공한다.
- 빈 사용자 그룹에는 중립 그룹 아이콘과 0을 표시한다. 문맥 표시 부모는 소속 수·Agent 구성에 포함하지 않는다.
- WORKSPACE의 전체/Claude/Codex 세션 필터는 유지한다. 이번 통합 대상은 그룹 목록이다.

### 세션 할당과 그룹 연결

- 세션 우클릭 메뉴에 “그룹 할당…”을 추가하고 기존 “세션 상세”를 유지한다. 모든 그룹 행에도 그룹 할당 메뉴를 제공한다.
- 할당 모달은 대상 이름, 선택 가능한 사용자 그룹, 현재 배정/연결 상태, 적용·취소 버튼을 보여준다. 같은 화면에서 새 그룹 생성 후 선택할 수 있다. 기존 다중 사용자 소속을 보존하도록 복수 선택을 허용한다.
- 세션 할당은 직접 소속을 편집한다. 그룹 할당은 원본 그룹에 대한 영구 연결을 편집하고 세션 목록을 복사하지 않는다. 둘의 효과를 모달 설명으로 구별한다.
- 자동 그룹을 사용자 그룹에 연결하면 해당 그룹의 현재 및 이후 세션이 사용자 그룹에 우선 표시된다. 배정된 세션은 자동 목록의 실제 소속에서 제외하고, 남는 세션이 없는 자동 항목은 숨긴다.
- 직접 수동 배정은 자동 그룹 연결보다 우선한다. 기존 다중 직접 소속은 유지한다. 사용자 그룹끼리의 연결은 소속 세션을 합집합으로 집계하며 중복 키를 한 번만 센다.
- 사용자 그룹도 다른 사용자 그룹에 연결할 수 있다. 선택 목록에서 자기 자신과 순환을 만드는 대상을 막고 저장 계층에서도 검증한다. 사이드바는 요청대로 평면 목록을 유지한다.
- 사용자가 할당 화면에서 선택을 해제하면 직접 배정/그룹 연결을 해제할 수 있다. 그룹 관리 화면에서도 현재 연결을 확인·해제할 수 있어, 자동 항목이 숨겨진 후에도 연결을 되돌릴 수 있다.
- 사용자 그룹 삭제 시 그 그룹을 가리키는 연결을 정리한다. 세션은 남은 직접 소속/연결 또는 기존 자동 분류로 돌아간다. 원본 세션이나 원본 그룹은 삭제하지 않는다.

### 분류와 저장

- 자동 분류의 기존 루트·이름·계정·호스트 경계는 유지한다. 직접 수동 소속 제외 → 자동 분류 산출 → 그룹 연결 적용 → 자동 잔여 항목 표시 순서로 계산하고, 연결 적용 후 자동 근거를 반복 재계산하지 않는다.
- 연결은 표시 이름이 아니라 안정적인 식별자로 저장한다. 사용자 그룹은 저장 ID, 원본 그룹/프로젝트는 제공자·계정·원본 ID·환경/호스트, 경로 그룹은 정규화 루트를 사용한다.
- 루트 한정 혼합 자동 그룹을 연결할 때에는 원본 대상과 해당 루트의 범위를 저장한다. 원본 그룹의 다른 경로로 연결이 확대되지 않도록 한다. 이름 변경만으로 연결이 끊기지 않게 한다.
- 원본 대상이 일시적으로 사라지면 연결을 보존하고 현재 기여 세션을 0으로 처리한다. 사용자가 해제할 수 있도록 원래 대상의 표시 정보를 유지한다.
- Desktop 전용 저장 모듈을 추가해 공용 Python/Tk GroupStore는 수정하지 않는다. 기존 version 1을 읽고, 최초 실제 편집 때 확장 형식으로 원자적으로 저장한다. 기존 id/name/members는 보존한다.
- 확장 형식은 구버전 Desktop 실행 파일의 읽기 호환을 보장하지 않는다. 신버전은 version 1과 새 형식을 모두 읽는다. 저장 형식은 Step 1에서 테스트로 고정하고 문서화한다.
- 잘못된 파일을 임의의 빈 그룹으로 덮어쓰지 않는다. 그룹 조회 실패 때 기존 오류 표시·쓰기 차단·자동 분류 중지 원칙을 유지한다.
- 모달이 열린 사이 대상/그룹이 삭제되거나 저장이 실패하면 성공으로 닫지 않는다. 새 목록을 기준으로 수정·재시도할 수 있게 한다. 그룹 생성 성공 후 할당이 실패한 경우 생성된 빈 그룹은 보존하고 실패를 표시한다.

## 가정과 미확인 사항

- 이름순 평면 목록, 다중 소속 유지, 사용자 그룹 간 연결, 직접 배정의 최우선 적용을 포함한 전체 계획을 사용자가 승인했다. 그룹 연결과 미래 세션 포함은 추가 답변으로도 확정했다.
- 현재 자동 그룹 식별에는 이름 기반 혼합 키도 있으므로 그 문자열 자체를 영구 연결 키로 사용하지 않는다.
- 사용자의 실제 그룹 파일 형식과 실행 중 프로세스 상태는 아직 읽지 않았다. 테스트에서는 임시 파일과 fixture만 변경하고 실제 사용자 배정은 수정하지 않는다.
- 새 외부 라이브러리는 필요하지 않다. 구현 도중 기존 구조로 해결할 수 없는 제품 정책이 발견되면 구현 전에 다시 확인한다.

## Step 1 — Desktop 그룹 연결 저장과 bridge

- 기존 사용자 그룹 v1 보존/재시작 복원과 새 영구 연결 저장을 Desktop 전용 모듈에 구현한다. 기존 create/rename/delete/member action이 연결 데이터를 유실하지 않도록 한다.
- 사용자 그룹 간 자기/순환 연결, 없는 대상 사용자 그룹, 중복 연결을 검증한다. 세션·그룹 할당 요청을 저장 단위에서 원자적으로 적용한다.
- snapshot에 연결 정보를 제공하고 할당 action을 추가한다. 기존 세션 키와 원본 메타데이터 응답은 보존한다.
- 검증: v1 읽기/전환, 편집 왕복, 새 인스턴스 복원, 이름 변경/삭제 참조 정리, 중복/순환 거부, 잘못된 파일·저장 실패 시 기존 파일 보존, provider/계정 경계. 관련 실패 재현 테스트 후 전체 Desktop Python 실행.
- 완료 기준: 원본 데이터를 건드리지 않고 현재 및 미래 세션을 연결할 식별자가 저장된다. 기존 그룹 API도 새 연결을 보존한다.
- 체크포인트 커밋: `Persist desktop group links and assignment updates`.

## Step 2 — 그룹 연결을 반영하는 공통 분류

- 하나의 공통 결과에서 직접 소속, 연결 소속, 자동 잔여 소속, 그룹별 세션 집합과 Agent 구성을 계산한다. UI 필터·검색·수·아이콘이 같은 소속 집합을 사용하도록 한다.
- 기존 수동 제외 및 부모 문맥 규칙을 보존한다. 자동 연결 적용 순서는 위 정책을 따르며 원본 메타데이터를 변경하지 않는다.
- 검증: 새 세션 유입, 직접 배정 우선, 다중/중첩 그룹의 중복 제거, 재연결·해제·삭제 후 복귀, 원본 이름 변경, 같은 이름 다른 계정/호스트/루트, 혼합 그룹의 루트 범위, 문맥 부모와 실제 소속 구별. 기존 Node 분류/트리 테스트도 실행한다.
- 완료 기준: 새로고침·입력 순서와 무관하게 소속과 잔여 자동 항목이 일치하며 새 연결 없이 기존 분류는 동일하다.
- 체크포인트 커밋: `Resolve linked groups with manual assignment priority`.

## Step 3 — 통합 Groups와 우클릭 할당 UX

- 하나의 이름순 Groups 목록, 실제 Agent/혼합 아이콘, 소속 수를 표시한다. 기존 메뉴 처리를 확장해 그룹과 세션 우클릭/키보드 진입을 지원한다.
- 할당 모달과 그 안의 새 그룹 생성, 적용·해제, 현재 연결 관리, 오류·진행 상태를 구현한다. 초기 포커스·Tab 범위·Escape 취소·닫은 뒤 포커스 복원을 확인한다.
- 검증: 목록 영역 통일, 양쪽 반반 아이콘, 두 대상별 메뉴, 목록 선택/복수 배정, 생성 직후 할당, 재시작 fixture 복원, 열린 모달 중 대상 소실, 저장 실패 후 재시도, 연결된 그룹의 새 세션 자동 유입, 연결 해제 후 복귀, 최소 960×640 창과 긴 그룹명. 검색·계층·상태·원래 key 열기는 기존 전체 Desktop Playwright로 확인한다.
- 최종 명령: `python -m unittest discover -s desktop -p 'test_*.py'`, 관련 Desktop Node 테스트, frontend의 `npx playwright test --config playwright.desktop.config.mjs`, `npm run check`, `scripts/build-desktop.ps1`.
- 빌드 화면을 캡처해 목록과 모달을 시각 검토한다. 실제 원본 앱 열기·사용자 그룹 편집 없이 fixture로 UX를 확인한다. 최종 실행 파일의 실제 WebView 검증 여부는 구분해 기록한다.
- 관련 기존 SPEC에 새 규칙을 반영하고 PLAN/HANDOFF에 테스트·리스크·적용 상태를 기록한다. 각 Step 및 최종 diff 범위 자체 검토와 `git diff --check`를 수행한다.
- 완료 기준: 요구 UX가 빌드 산출물에 반영되고 테스트·화면 확인이 통과하며 기존 동작 회귀가 없다.
- 체크포인트 커밋: `Unify Groups and add session and group assignment dialogs`.
